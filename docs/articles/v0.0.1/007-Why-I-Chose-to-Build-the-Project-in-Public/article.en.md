# Why I Chose to Build the Project in Public

[Medium](https://tareknajem04.medium.com/ai-assisted-professional-engineering-with-net-3bfe7224aecd)
[LinkedIn](https://www.linkedin.com/pulse/ai-assisted-professional-engineering-net-tarek-najem-evf5e)

Many engineering projects appear only after they are finished.

The repository is clean.

The documentation looks polished.

Every feature seems intentional.

What remains invisible is the journey that produced it.

The experiments.

The mistakes.

The discarded ideas.

The architectural debates.

Those are often the most valuable parts of any engineering project.

I wanted to preserve them.

Not because they prove success.

But because they explain the reasoning behind every decision.

This repository is more than source code.

It is an engineering journal.

Architectural decisions are documented.

Publishing workflows evolve in public.

Ideas are revised instead of erased.

Even unsuccessful experiments become part of the project's history.

That level of transparency may seem unusual.

Traditional software development often hides the process and reveals only the result.

I chose the opposite approach.

The process is the product.

Because software eventually becomes outdated.

Technologies evolve.

Frameworks change.

But engineering decisions—and the reasoning behind them—continue to teach long after the code itself has been replaced.

Building in public also changes accountability.

When decisions are visible, they are easier to challenge.

When mistakes are documented, they become opportunities to learn.

When progress is shared incrementally, improvement becomes continuous rather than occasional.

This approach requires accepting imperfection.

Not every experiment succeeds.

Not every architectural decision survives.

Not every release is impressive.

That is precisely why the journey deserves to be documented.

If this repository helps someone avoid a mistake I already made, then publishing the process was worth it.

If it inspires someone to document their own engineering decisions, then it achieved something even more valuable.

Perhaps open source is not only about sharing code.

Perhaps it is also about sharing how we think.
